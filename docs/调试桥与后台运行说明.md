# 调试桥、非活动页面与关闭行为

## “标签页非活动”与 CDP

DevTools 前端提示目标非活动，通常表示目标 WebView 不是当前可见/前台内容。它不代表本地 WebSocket 必然断开。MCP 和手工 DevTools 都连接调试桥的 `ws://127.0.0.1:62000`，桥再将 CDP 请求封装成 WMPF 私有协议送入运行时。请求转发不依赖 HWND 的前台焦点。

实际后台验证中，测试最小化了本次自产会话进程树内可见窗口，并从目标上下文读取到：

```json
{"visibility":"hidden","value":42}
```

随后 MCP 与另一条独立 WebSocket 连接同时发送 `id=2` 的 `Runtime.evaluate`，表达式均为 `6*7`，两边都收到自己的 `42`。这证明页面处于 hidden 时协议通道仍可用；不证明页面定时器、动画、渲染和异步业务仍按前台速率运行。若引擎冻结或回收上下文，相关命令仍会超时或报上下文不存在。

可通过 MCP 检查：

```text
cdp_connect {}
cdp_evaluate {"expression":"JSON.stringify({visibility:document.visibilityState, url:location.href})"}
cdp_evaluate {"expression":"6*7"}
```

也可用独立 CDP 客户端连 `ws://127.0.0.1:62000`。前端提示非活动时先用上述求值确认 target 是否仍能响应。

## MCP 与 DevTools 同时连接

之前桥把每条命令广播给所有运行时客户端，并把返回结果广播给每个 CDP 客户端。不同客户端复用相同 JSON-RPC request ID 时可能串错响应。本版为每条上行请求分配唯一代理 ID，维护发起客户端与原始 ID 的对应关系；只将返回结果送回发起端，运行时事件仍广播给所有连接端。断开的客户端所持未完成请求会被移除。MCP 客户端自身也会在超时/发送失败后释放待处理请求，并串行写 WebSocket。

## DevTools 图形前端限制

可尝试：

```text
devtools://devtools/bundled/inspector.html?ws=127.0.0.1:62000
```

本地调试桥不是 Chromium 的标准 `/json/list` 发现服务器，而是直连一个目标 WebSocket。当前运行时版本对 `Page.getFrameTree` 的结果处理存在已确认崩溃问题；桥因此明确对该命令返回 `-32601`，不转发到运行时。DevTools 的帧树/部分页面面板会受到影响。后台 CDP 的成功验证不等于完整 DevTools 图形界面或所有域都通过验收。

本机当前无可从命令行发现的 Chrome/Edge 可执行程序，所以本轮没有自动化完整的 `devtools://` 前端 GUI；独立协议客户端、多客户端并发和 MCP 路径已实测。

## `wmpfhost` 与关闭

自产 `wmpfhost_integrated.exe` 仍是必须的运行时宿主，Windows 进程列表仍会显示它。宿主创建的空白 `wmpf host` HWND 保持有效但默认隐藏，避免空窗口抢前台或被误认成小程序窗口。宿主 HWND 收到 `WM_CLOSE` 会设置退出标志；宿主结束后 observer 跳出等待并清理本次宿主及运行时子进程。真实测试对隐藏 HWND 投递 `WM_CLOSE`，会话变为 `closed`，observer 的 `remaining_pids` 为空。

GUI 的“后台隐藏小程序窗口”是另一个独立选项，默认关闭。启用后 observer 仅对本次创建并跟踪的自产宿主/运行时进程枚举顶层窗口，并持续处理后续新建窗口；其他程序窗口不受影响。CDP 输入事件可以继续经调试桥发送，但隐藏页面的定时器、动画和渲染可能被运行时节流。

工作台自身的关闭按钮会结束本次会话并停止两项托管服务。使用独立临时配置进行真实窗口关闭测试，GUI 进程退出且两项服务均停止。复验报告：`out/gui-close-verification.json`。
